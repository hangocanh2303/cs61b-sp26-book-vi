# 25.3 Contains & phần tử trùng lặp

## Contains

### Phương thức `equals()` cho đối tượng ColoredNumber

Giả sử phương thức `equals()` cho ColoredNumber như dưới đây, tức hai ColoredNumber bằng nhau nếu chúng có cùng `num`.

```java
@Override
public boolean equals(Object o) {
   if (o instanceof ColoredNumber otherCn) {
       return this.num == otherCn.num;
   }
   return false;
}
```

### Hành vi của HashSet khi kiểm tra `contains()`

Giả sử phương thức `equals()` cho ColoredNumber như trên, tức hai ColoredNumber bằng nhau nếu có cùng `num`.&#x20;

```java
int N = 20;
HashSet<ColoredNumber> hs = new HashSet<>();
for (int i = 0; i < N; i += 1) {
    hs.add(new ColoredNumber(i));
}
```

Giả sử giờ ta kiểm tra 12 có trong bảng băm không.

```java
ColoredNumber twelve = new ColoredNumber(12);
hs.contains(twelve); //returns true
```

{% hint style="info" %}
Ta **kỳ vọng** `contains` trả về gì?
{% endhint %}

<details>

<summary>Đáp án</summary>

Ta kỳ vọng lời gọi `contains` trả về true — mọi số `12` đều bằng nhau!

</details>

### Tìm phần tử dùng hashCode mặc định

Giả sử ta dùng hàm băm mặc định (dùng địa chỉ bộ nhớ):

```java
int N = 20;
HashSet<ColoredNumber> hs = new HashSet<>();
for (int i = 0; i < N; i += 1) {
   hs.add(new ColoredNumber(i));
}
ColoredNumber twelve = new ColoredNumber(12);
hs.contains(twelve); // returns ??
```

cho ra bảng dưới đây:

![](https://lh4.googleusercontent.com/cFvLVhOYg31lSg1a8moftrr30qpThw3Bc7drJWVLNrSTCgTdO4yxjis1epmRlRMLWIkh73alL6OrblQxqGGrjMo1XMoOfPjSFH3tPDDbaxSbLXe1-HXJcfQOglsU4Dp74PiDDqMWXNOmYeQu_D7-l_B2SBcdTVohYMYLZdnzzMVn8_hAbvSKDAKyC-_ev3nN=s2048)

Giả sử equals trả về true nếu hai ColoredNumber có cùng num (như đã định nghĩa trước đó).

{% hint style="info" %}
`contains` thực sự trả về gì?
{% endhint %}

<details>

<summary>Đáp án</summary>

Trả về false với xác suất 5/6.

`hashCode()` mặc định dựa trên địa chỉ bộ nhớ. `equals` dựa trên `num`.

Có hai đối tượng ColoredNumber có `num = 12`. Một trong số đó nằm trong HashSet và một được tạo bởi đoạn mã ở trên.

Mỗi địa chỉ bộ nhớ là ngẫu nhiên, chỉ có xác suất 1/6 chúng mod ra cùng bucket.

Ví dụ: Nếu đối tượng `ColoredNumber` `twelve` tạo bởi đoạn mã trên nằm ở vị trí bộ nhớ 6000000, hashCode % 6 = 0. HashSet tìm trong bucket 0 và không thấy 12.

</details>

{% hint style="info" %}
Câu hỏi khó: Nếu mã băm mặc định đã cho phân bố tốt, tại sao ta vẫn bận tâm tạo hàm băm tùy chỉnh?&#x20;
{% endhint %}

<details>

<summary>Đáp án</summary>

Cần có sự nhất quán giữa `equals()` và `hashCode()` để các thao tác trên bảng băm hoạt động đúng.

</details>

**Quy tắc cơ bản (cũng là định nghĩa tính tất định của hashCode hợp lệ):** Nếu hai đối tượng bằng nhau, chúng **phải** có cùng mã băm để bảng băm có thể tìm thấy nó.

### Ghi đè `equals()` nhưng không ghi đè `hashCode()`

Giả sử ta có cùng phương thức `equals()` (so sánh `num`), nhưng ta không ghi đè `hashCode()`.

```java
public boolean equals(Object o) {
   ...  return this.num == otherCn.num; ...
}
```

Kết quả khi thêm 0 đến 19 được hiển thị bên dưới:

![](<../../.gitbook/assets/image (10).png>)

```java
ColoredNumber zero = new ColoredNumber(0);
hs.add(zero); // liệu có thêm một số 0 nữa không?
```

{% hint style="info" %}
Điều nào có thể xảy ra khi ta gọi add(zero)?

Các lựa chọn:

1. Ta thêm một số 0 vào bin 0.
2. Ta thêm một số 0 vào bin 1.
3. Ta thêm một số 0 vào bin khác.
4. Ta không tạo ra số 0 trùng lặp.
{% endhint %}

<details>

<summary>Đáp án</summary>

3 lựa chọn đúng:

\#1, #3, #4.

Ta thêm 0 vào bin 0, ta thêm 0 vào bin khác, và ta không có số 0 trùng.

Số 0 mới sẽ rơi vào bin ngẫu nhiên.

* Xác suất 5/6: Ở bin 0, 2, 3, 4, hoặc 5. Trùng lặp!
* Xác suất 1/6: Ở bin 1, không trùng! (`equals()` chặn lại)

</details>

## Bài học quan trọng: `equals()` và `hashCode()`

Kết luận: Nếu lớp của bạn ghi đè equals, bạn cũng nên ghi đè hashCode một cách nhất quán.

* Nếu hai đối tượng bằng nhau, chúng phải luôn có cùng mã băm.\


Nếu bạn không làm vậy, mọi thứ sẽ hỏng:

* `Contains` không thể tìm thấy đối tượng (trừ khi may mắn).
* `Add` dẫn đến phần tử trùng lặp.
