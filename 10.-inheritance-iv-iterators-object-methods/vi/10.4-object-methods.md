# 10.4 Các phương thức của Object

Mọi lớp đều kế thừa từ lớp gốc `Object`. Các phương thức được kế thừa gồm:

* `String toString()`
* `boolean equals(Object obj)`
* `Class <?> getClass()`
* `int hashCode()`
* `protected Objectclone()`
* `protected void finalize()`
* `void notify()`
* `void notifyAll()`
* `void wait()`
* `void wait(long timeout)`
* `void wait(long timeout, int nanos)`

Trong chương này ta tập trung vào **hai** phương thức đầu. Ta sẽ dùng kế thừa để **ghi đè** hai phương thức này trong các lớp của mình cho đúng hành vi mong muốn.

## toString() <a href="#tostring" id="tostring"></a>

{% embed url="https://www.youtube.com/watch?v=AKnMv0ootkg" %}

Phương thức `toString()` cung cấp biểu diễn dạng chuỗi của một đối tượng. Hàm `System.out.println()` **ngầm** gọi `toString()` lên đối tượng được truyền vào rồi in chuỗi trả về. Khi chạy `System.out.println(dog)`, thực chất tương đương với:

```java
String s = dog.toString()
System.out.println(s)
```

Mặc định, `toString()` của lớp `Object` in ra **vị trí** của đối tượng trong bộ nhớ — một chuỗi dạng hex. Các lớp như `ArrayList` và mảng Java có phiên bản `toString()` đã ghi đè. Vì vậy khi làm việc và viết kiểm thử với `ArrayList`, kết quả in ra thường là danh sách dạng dễ đọc như `(1, 2, 3, 4)` thay vì chỉ in địa chỉ ô nhớ.

Với các lớp tự viết như `ArrayDeque`, `LinkedListDeque`, v.v., ta cần tự cung cấp `toString()` nếu muốn in ra dạng có thể đọc được.

Hãy thử viết phương thức này cho lớp `ArraySet`. Đọc lớp `ArraySet` dưới đây và đảm bảo hiểu các phương thức làm gì. Có thể dán mã vào Java Visualizer để hình dung rõ hơn.

```java
import java.util.Iterator;

public class ArraySet<T> implements Iterable<T> {
    private T[] items;
    private int size; // the next item to be added will be at position size

    public ArraySet() {
        items = (T[]) new Object[100];
        size = 0;
    }

    /* Returns true if this map contains a mapping for the specified key.
     */
    public boolean contains(T x) {
        for (int i = 0; i < size; i += 1) {
            if (items[i].equals(x)) {
                return true;
            }
        }
        return false;
    }

    /* Associates the specified value with the specified key in this map.
       Throws an IllegalArgumentException if the key is null. */
    public void add(T x) {
        if (x == null) {
            throw new IllegalArgumentException("can't add null");
        }
        if (contains(x)) {
            return;
        }
        items[size] = x;
        size += 1;
    }

    /* Returns the number of key-value mappings in this map. */
    public int size() {
        return size;
    }

    /** returns an iterator (a.k.a. seer) into ME */
    public Iterator<T> iterator() {
        return new ArraySetIterator();
    }

    private class ArraySetIterator implements Iterator<T> {
        private int wizPos;

        public ArraySetIterator() {
            wizPos = 0;
        }

        public boolean hasNext() {
            return wizPos < size;
        }

        public T next() {
            T returnItem = items[wizPos];
            wizPos += 1;
            return returnItem;
        }
    }

    @Override
    public String toString() {
        /* hmmm */
    }


    @Override
    public boolean equals(Object other) {
        /* hmmm */
    }

    public static void main(String[] args) {
        ArraySet<Integer> aset = new ArraySet<>();
        aset.add(5);
        aset.add(23);
        aset.add(42);

        //iteration
        for (int i : aset) {
            System.out.println(i);
        }

        //toString
        System.out.println(aset);

        //equals
        ArraySet<Integer> aset2 = new ArraySet<>();
        aset2.add(5);
        aset2.add(23);
        aset2.add(42);

        System.out.println(aset.equals(aset2));
        System.out.println(aset.equals(null));
        System.out.println(aset.equals("fish"));
        System.out.println(aset.equals(aset));
}
```

**Bài tập 6.4.1:** Viết `toString()` sao cho khi in một `ArraySet`, các phần tử được in cách nhau bởi dấu phẩy, nằm trong cặp ngoặc nhọn, ví dụ `{1, 2, 3, 4}`. Nhớ `toString()` phải **trả về** một `String`.

**Lời giải**

```java
public String toString() {
    String returnString = "{";
    for (int i = 0; i < size; i += 1) {
        returnString += keys[i];
        returnString += ", ";
    }
    returnString += "}";
    return returnString;
}
```

Lời giải này trông đơn giản, nhưng thực ra khá ngây thơ: khi nối chuỗi trong Java kiểu `returnString += keys[i];`, ta không chỉ “thêm vào” `returnString`, mà đang **tạo một chuỗi mới**. Điều đó rất tốn vì tạo đối tượng chuỗi mới cũng tốn thời gian — cụ thể là tuyến tính theo độ dài chuỗi (lý do sẽ nói ở chương sau).

**Câu hỏi thêm:** Giả sử nối một ký tự vào một chuỗi mất 1 giây. Với `ArraySet` có kích thước 5: `{1, 2, 3, 4, 5}`, chạy `toString()` theo cách trên mất bao lâu?

**Đáp án:** Gán `returnString` bằng dấu `{` mất 1 giây vì tương đương nối `{` vào chuỗi rỗng `""`. Thêm phần tử đầu tiên tạo chuỗi hoàn toàn mới, gồm `{` và `1`, mất 2 giây. Phần tử thứ hai mất 3 giây vì phải gồm `{`, `1`, `2`. Quy luật tiếp diễn, tổng thời gian cho cả `ArraySet` là `1 + 2 + 3 + 4 + 5 + 6 + 7.`

Để khắc phục, Java có lớp `StringBuilder`. Nó biểu diễn chuỗi **có thể thay đổi**, nên có thể `append` liên tục vào cùng một đối tượng thay vì mỗi lần tạo chuỗi mới.

**Bài tập 6.4.2:** Viết lại `toString()` dùng `StringBuilder`.

**Lời giải**

```java
public String toString() {
        StringBuilder returnSB = new StringBuilder("{");
        for (int i = 0; i < size - 1; i += 1) {
            returnSB.append(items[i].toString());
            returnSB.append(", ");
        }
        returnSB.append(items[size - 1]);
        returnSB.append("}");
        return returnSB.toString();
    }
```

Như vậy ta đã ghi đè thành công `toString()`. Thử in `ArraySet` để xem kết quả.

Tiếp theo ta ghi đè một phương thức quan trọng khác của `Object`: `equals()`.

## equals() <a href="#equals" id="equals"></a>

{% embed url="https://www.youtube.com/watch?v=qHuS1o97nfQ" %}

`equals()` và `==` có hành vi khác nhau trong Java. `==` kiểm tra hai biến có **cùng giá trị trong ô** hay không (nhớ Java truyền tham trị): với kiểu nguyên thủy là so sánh giá trị; với tham chiếu là hai biến có **cùng trỏ tới một đối tượng** (cùng địa chỉ) hay không.

Xét lớp `Doge` sau:

```java
public class Doge {

   public int age;
   public String name;

   public Doge(int age, String name){
      this.age = age;
      this.name = name;
   }
   public static void main(String[] args) {

      int x = 5;
      int y = 5;
      int z = 6;

      Doge fido = new Doge(5, "Fido");
      Doge doggo = new Doge(6, "Doggo");
      Doge fidoTwin = new Doge(5, "Fido");
      Doge fidoRealTwin = fido;
   }
}
```

**Bài tập 6.4.3:** Java trả về gì với các biểu thức sau?

* `x == y`
* `x == z`
* `fido == doggo`
* `fido == fidoTwin`
* `fido == fidoRealTwin`

**Đáp án**

* `True`
* `False`
* `False`
* `False`
* `True`

`fido` và `fidoTwin` **không** thỏa `==` vì trỏ tới hai đối tượng khác nhau, dù thuộc tính giống nhau. Điều này cho thấy `==` dễ gây khó khi viết kiểm thử trong Java. Khi kiểm thử `ArrayList`, ta tạo `expected` là một `ArrayList` mới; nếu dùng `==` thì gần như luôn `false`. Đó là lúc cần `equals(Object o)`.

## `equals(Object o)` <a href="#equalsobject-o" id="equalsobject-o"></a>

`equals(Object o)` trong lớp `Object` mặc định hoạt động giống `==`: so địa chỉ của `this` và `o`. Ta có thể ghi đè để định nghĩa “bằng nhau” theo ý muốn. Ví dụ, hai `ArrayList` được coi bằng nhau nếu có cùng các phần tử theo cùng thứ tự.

**Bài tập 6.4.4:** Viết `equals` cho lớp `ArraySet`. Nhớ set là tập **không thứ tự** các phần tử **duy nhất**. Hai set bằng nhau nếu có cùng tập phần tử (không cần cùng thứ tự lưu trữ).

**Lời giải**

```java
public boolean equals(Object other) {
        if (this == other) {
            return true;
        }
        if (other == null) {
            return false;
        }
        if (other.getClass() != this.getClass()) {
            return false;
        }
        ArraySet<T> o = (ArraySet<T>) other;
        if (o.size() != this.size()) {
            return false;
        }
        for (T item : this) {
            if (!o.contains(item)) {
                return false;
            }
        }
        return true;
    }
```

Ta thêm vài kiểm tra đầu hàm để xử lý `null` và đối tượng khác lớp; đồng thời tối ưu bằng cách trả về `true` ngay khi `==` trên hai tham chiếu cho `true`, tránh duyệt thừa.

**Quy tắc cho `equals` trong Java:** Ghi đè `equals()` đôi khi tinh vi hơn vẻ ngoài. Một số nguyên tắc:

1.) `equals` phải là **quan hệ tương đương**:

* **phản xạ**: `x.equals(x)` là `true`
* **đối xứng**: `x.equals(y)` khi và chỉ khi `y.equals(x)`
* **bắc cầu**: `x.equals(y)` và `y.equals(z)` suy ra `x.equals(z)`

2.) Phải nhận tham số kiểu `Object` để thực sự ghi đè `equals()` gốc.

3.) **Ổn định**: nếu `x.equals(y)` và `x`, `y` không đổi, thì `x.equals(y)` vẫn đúng.

4.) Với `null` luôn sai: `x.equals(null)` phải là `false`.
