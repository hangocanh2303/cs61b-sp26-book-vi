# 10.2 Exceptions (ngoại lệ)

Trong phần này, ta học cách **ném** (throw) ngoại lệ để xử lý có kiểm soát các lỗi có thể xảy ra trong chương trình.

{% embed url="https://youtu.be/r5hp67RfWaY" %}

Phần triển khai `ArraySet` ở phần trước có một lỗi nhỏ: khi thêm `null` vào `ArraySet`, chương trình ném `NullPointerException`.

Vấn đề nằm ở phương thức `contains`, nơi ta kiểm tra `items[i].equals(x)`. Nếu phần tử tại `items[i]` là `null`, lệnh tương đương là gọi `null.equals(x)` → `NullPointerException`.

Ngoại lệ làm **dừng** luồng điều khiển thông thường. Ta cũng có thể **chủ động** ném ngoại lệ. Trong Python có thể đã gặp với từ khóa `raise`. Trong Java, ngoại lệ là đối tượng; ta ném ngoại lệ theo dạng:

`throw new ExceptionObject(thamSo1, ...)`

\
Hãy ném một ngoại lệ khi người dùng cố thêm `null` vào `ArraySet`. Ta sẽ ném `IllegalArgumentException`, nhận một tham số (chuỗi thông báo kiểu `String`).

Phương thức `add` đã cập nhật:

```java
/* Associates the specified value with the specified key in this map.
   Throws an IllegalArgumentException if the key is null. */
public void add(T x) {
    if (x == null) {
        throw new IllegalArgumentException("can't add null");
    }
    if (contains(x)) {
        return;
    }
    items[size] = x;
    size += 1;
}
```

Dù kết quả vẫn là một ngoại lệ — vậy cách làm này **tốt hơn** ở điểm nào?

1. Ta **kiểm soát** được mã: tự quyết định điểm dừng của luồng thực thi.
2. Có kiểu ngoại lệ phù hợp hơn và thông báo lỗi hữu ích cho người dùng API.

Tuy nhiên, đôi khi ta muốn chương trình **không** crash. Có nhiều hướng xử lý; ví dụ:

**Cách 1**: Không thêm `null` vào mảng khi `add` nhận `null`.&#x20;

**Cách 2**: Sửa `contains` để xử lý trường hợp `items[i] == null`.

Dù chọn cách nào, điều quan trọng là người dùng API biết **kỳ vọng** gì — vì vậy tài liệu (ví dụ ghi chú về hành vi phương thức) rất quan trọng.\
