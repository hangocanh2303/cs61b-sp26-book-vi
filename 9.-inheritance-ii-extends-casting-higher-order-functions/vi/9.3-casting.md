# 9.3 Viết hàm max

Ta đã thấy Java cung cấp sẵn hàm `Collections.max` khá tiện. `Collections` còn có các hàm hữu ích khác như `min`, `sort`, và `reverse`.

Trong chương này ta sẽ xem cách tự viết những hàm như vậy.

## Hàm generic (khởi động — *warmup*)

Phần khởi động: giả sử ta muốn một hàm chọn ngẫu nhiên một phần tử từ một mảng. Đoạn mã dưới đây minh họa ý đó:

```java
public class RandomPicker {
    public static <T> T randomItem(T[] items) {
        Random random = new Random();
        int randomIndex = random.nextInt(x.length);
        return x[randomIndex];
    }
}
```

Và một chương trình mẫu dùng hàm này:

```java
public class RandomPickerDemo {
   public static void main(String[] args) {
       String[] x = {"hi", "little", "cat"};
       System.out.println(RandomPicker.pickRandom(x));
   }
}
```

Tiếp theo, ta sẽ cố gắng làm cho hàm `pickRandom` có thể làm việc với mảng thuộc bất kỳ kiểu nào.

### Cách một: Generics

Ta có thể thử dùng generics, như trong đoạn dưới đây:

```java
public class RandomPicker<T> {
   public static T pickRandom(T[] x) {
       Random random = new Random();
       int randomIndex = random.nextInt(x.length);
       return x[randomIndex];
   }
}
```

Tuy nhiên, mã này không thực sự hợp lý như đã viết. Hàm `pickRandom` là `static`, nhưng ta lại phải khởi tạo một đối tượng `RandomPicker` để chỉ định kiểu generic. Tức là ta cần làm kiểu như:

```java
String[] x = {"hi", "little", "cat"};
RandomPicker<String> stringPicker = new RandomPicker<>();
System.out.println(stringPicker.pickRandom(x));
```

nhưng ta không thể gọi phương thức `static` thông qua một đối tượng thực thể.

Một cách sửa là làm hàm `pickRandom` không còn `static`, như dưới đây:

```java
public class RandomPicker<T> {
   public T pickRandom(T[] x) {
       Random random = new Random();
       int randomIndex = random.nextInt(x.length);
       return x[randomIndex];
   }
}
```

Nếu làm vậy mã sẽ chạy ổn, nhưng vẫn rất vụng về khi phải khởi tạo một đối tượng picker.

### Cách hai: Phương thức static generic

Cách đúng và tốt hơn là làm phương thức `static` của ta trở thành generic. Như dưới đây:

```java
public class RandomPicker {
   public static <T> T pickRandom(T[] x) {
       Random random = new Random();
       int randomIndex = random.nextInt(x.length);
       return x[randomIndex];
   }
}
```

Cú pháp này gây rối (và sau này còn tệ hơn!). Cách đọc `public static <T> T pickRandom(T[] x)` là: “Tôi khai báo một hàm `public static` làm việc với đối tượng kiểu `<T>`, nó trả về `T`, tên là `pickRandom`, và nhận vào một mảng các phần tử kiểu `T`.”

Sau khi báo cho Java biết phương thức `static` của ta là generic, ta có thể gọi nó mà không cần khởi tạo đối tượng `RandomPicker`, như dưới đây:

```java
public class RandomPickerDemo {
   public static void main(String[] args) {
       String[] x = {"hi", "little", "cat"};
       System.out.println(RandomPicker.pickRandom(x));
   }
}
```

Lưu ý rằng khác với lớp generic, ta không cần chỉ định kiểu generic khi gọi một phương thức `static` generic (tức không có `<String>` sau `pickRandom`). Kiểu được suy luận tự động.

Một điểm phiền phức nhỏ là hàm `pickRandom` của ta sẽ không hoạt động với mảng kiểu nguyên thủy, ví dụ `int[]`, `double[]`, `float[]`.

```java
public class RandomPickerDemo {
   public static void main(String[] args) {
       int[] x = {1, 2, 3, 4, 5, 6, 7, 8};
       System.out.println(RandomPicker.pickRandom(x));
   }
}
```

Không có cách nào né tránh điều này, và trong thực tế các thư viện Java thường phải có nhiều phiên bản hàm, mỗi phiên bản cho một kiểu nguyên thủy. Ví dụ có `Arrays.sort(int[])`, `Arrays.sort(double[])`, `Arrays.sort(float[])`, v.v. Có lẽ một ngày nào đó Project Valhalla sẽ giải quyết chuyện này.

## Viết hàm max của ta, ràng buộc kiểu (type bounds)

Dùng ý tưởng về hàm `static` generic, ta có thể viết hàm `max` như sau:

```java
public class Maximizer {
   public static <T> T max(T[] items) {
       T maxItem = items[0];
       for (int i = 0; i < items.length; i += 1) {
           int cmp = items[i].compareTo(maxItem);
           if (cmp > 0) {
               maxItem = items[i];
           }
       }
       return maxItem;
   }
}
```

Còn một vấn đề cuối: Java không biết `T` có phương thức `compareTo`. Ta có thể sửa bằng cách thêm **ràng buộc kiểu** (type bound) cho kiểu generic, như dưới đây:

```java
public class Maximizer {
   public static <T extends Comparable<T>> T max(T[] items) {
       T maxItem = items[0];
       for (int i = 0; i < items.length; i += 1) {
           int cmp = items[i].compareTo(maxItem);
           if (cmp > 0) {
               maxItem = items[i];
           }
       }
       return maxItem;
   }
}
```

Điều này báo cho Java biết `T`, dù là gì, phải triển khai `Comparable<T>`. Nếu bạn cố truyền vào `max` một mảng các đối tượng không triển khai `Comparable<T>`, bạn sẽ gặp lỗi biên dịch.

Cách đọc `public static <T extends Comparable<T>> T max(T[] items)` là: “Tôi khai báo một hàm `public static` làm việc với đối tượng kiểu `<T>`, nó trả về `T`, tên là `max`, và nhận vào một mảng các phần tử kiểu `T`. Ngoài ra, `T` phải triển khai `Comparable<T>`.”

### Phần thêm: Một ràng buộc kiểu còn tốt hơn

Trong mã Java “công nghiệp” thực tế, cách đúng để khai báo phương thức của ta là:

```java
public class Maximizer {
   public static <T extends Comparable<? super T>> T max(T[] items) {
		...
   }
}
```
