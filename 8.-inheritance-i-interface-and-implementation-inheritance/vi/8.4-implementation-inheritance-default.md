# 8.4 Kế thừa cài đặt, default



Trước đây, interface `List61B` chỉ có phần khai báo phương thức, nêu **cần làm gì** chứ chưa nói **làm thế nào**. Giờ ta sẽ thấy có thể viết ngay trong `List61B` những phương thức đã có thân (cài đặt) đầy đủ — chúng mô tả **cách** các kiểu con của `List61B` có thể hành xử theo mặc định.

Để làm vậy, bạn phải có từ khóa `default` trong chữ ký phương thức.

Nếu ta định nghĩa phương thức này trong `List61B`

```java
default public void print() {
    for (int i = 0; i < size(); i += 1) {
        System.out.print(get(i) + " ");
    }
    System.out.println();
}
```

Thì mọi lớp nào `implements List61B` đều có thể dùng phương thức đó!

Tuy nhiên, có một điểm không hiệu quả nhỏ trong phương thức này. Bạn có nhận ra không?

Với `SLList`, mỗi lần gọi `get` phải bước dọc cả danh sách; cách in mặc định lặp `get(i)` vì vậy rất tốn. Hiệu quả hơn là duyệt một lần và in dọc đường đi!

Ta muốn `SLList` in theo cách khác với bản mặc định trong interface. Để làm vậy, ta ghi đè. Trong `SLList`, ta cung cấp phương thức sau:

```java
@Override
public void print() {
    for (Node p = sentinel.next; p != null; p = p.next) {
        System.out.print(p.item + " ");
    }
}
```

Giờ, mỗi khi ta gọi `print()` trên một `SLList`, phương thức này sẽ được gọi thay cho phương thức trong `List61B`.
