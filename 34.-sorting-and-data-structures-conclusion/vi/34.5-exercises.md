# 34.5 Bài Tập

## Thực Hành (Factual)

1. Điều gì xảy ra khi một file Java được biên dịch? GỢI Ý: Nghĩ về file `.java` và `.class`.
2. Tại sao một khối code có thể chạy nhanh hơn lần thứ hai so với lần đầu tiên?
3. Cách tối ưu để sắp xếp mảng số nguyên là gì? Giả sử các số nguyên phân bố ngẫu nhiên đều.

<details>

<summary>Bài 1</summary>

Khi một file Java được biên dịch, nó được chuyển từ định dạng mã nguồn `.java` dễ đọc cho người thành byte code trong định dạng file `.class` có thể được thực thi bởi Java Virtual Machine (JVM).

</details>

<details>

<summary>Bài 2</summary>

Nếu một đoạn code được gọi nhiều lần, trình thông dịch nghiên cứu và cài đặt lại code dựa trên những gì được quan sát trong khi code đang chạy. Ví dụ, nếu bạn tạo nhiều cấu trúc dữ liệu không sử dụng, chúng có thể bị tối ưu ra khỏi code.

</details>

<details>

<summary>Bài 3</summary>

Như ta đã thấy trong bài giảng, LSD sort vượt trội quicksort cho mảng số nguyên, đặc biệt nếu ta tối ưu cho cơ số tốt hơn cơ số 10.

</details>

## Siêu Nhận Thức (Metacognitive)

1. Trong điều kiện nào LSD sort sẽ nhanh hơn mergesort?

<details>

<summary>Bài 1</summary>

Có hai trường hợp chính khi LSD sort nhanh hơn nhiều so với mergesort: khi có số lượng chuỗi lớn (N lớn), và khi tất cả chuỗi rất giống nhau.

Khi N thực sự lớn, ta thấy hành vi tiệm cận của LSD sort vượt qua hành vi tiệm cận của merge sort, vốn chậm hơn với thời gian chạy $$N \log N$$.

Khi các chuỗi rất giống nhau, thì mỗi phép so sánh trong merge sort chậm, xấp xỉ thời gian tuyến tính theo độ dài chuỗi. Thay vì so sánh mỗi ký tự trong mỗi chuỗi ở mỗi lần trộn, LSD chỉ kiểm tra các ký tự của mỗi chuỗi một lần.

</details>
