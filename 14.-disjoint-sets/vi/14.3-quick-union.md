# 14.3 Quick Union

Giả sử ta ưu tiên làm cho thao tác `connect` nhanh. Ta vẫn biểu diễn các tập bằng một mảng. Thay vì lưu mã tập (`id`), ta gán cho mỗi phần tử **chỉ số của cha** trong cây. Nếu một phần tử không có cha thì nó là **gốc** (root) và ta gán cho nó một giá trị âm.

Cách này cho phép ta hình dung mỗi tập như một cây. Ví dụ, ta biểu diễn `{0, 1, 2, 4}, {3, 5}, {6}` như sau:

&#x20;Chú ý rằng ta chỉ dùng **một mảng** để biểu diễn các tập. Ta tự hình dung nó dưới dạng cây.

<figure><img src="https://joshhug.gitbooks.io/hug61b/content/chap9/9.3.1.png" alt=""><figcaption></figcaption></figure>

Với QuickUnion ta định nghĩa phương thức phụ `find(int item)` trả về gốc của cây mà `item` nằm trong đó. Ví dụ, với các tập trên, `find(4) == 0`, `find(1) == 0`, `find(5) == 3`, v.v. Mỗi phần tử có đúng một gốc.

**`connect(x, y)`**

Để nối hai phần tử, ta tìm tập mà mỗi phần tử thuộc (gốc của cây tương ứng), rồi làm cho một gốc trở thành con của gốc kia. Ví dụ:

`connect(5, 2)`:

1. `find(5)` -> 3
2. `find(2)` -> 0
3. Đặt cha của nút `find(5)` là `find(2)`, tức `parent[3] = 0`

&#x20;Chú ý phần tử 3 giờ trỏ tới phần tử 0, gộp hai cây/hai tập thành một.

<figure><img src="https://joshhug.gitbooks.io/hug61b/content/chap9/9.3.2.png" alt=""><figcaption></figcaption></figure>

Trong trường hợp tốt nhất, nếu `x` và `y` đều là gốc của cây của chúng thì `connect(x, y)` chỉ cần cho `x` trỏ tới `y`, một thao tác Θ(1)! (Vì vậy mới có tên QuickUnion)

**`isConnected(x, y)`**

Nếu hai phần tử thuộc cùng một tập thì chúng nằm trên cùng một cây. Do đó chúng có cùng gốc. Vậy với `isConnected(x, y)` ta chỉ cần kiểm tra `find(x) == find(y)`.

### Hiệu năng <a href="#performance" id="performance"></a>

QuickUnion có một vấn đề hiệu năng tiềm ẩn: cây có thể trở nên rất dài. Khi đó, việc tìm gốc của một phần tử (`find(item)`) trở nên rất tốn kém. Xét cây dưới đây:

![](https://joshhug.gitbooks.io/hug61b/content/chap9/9.3.3.png)

Trong trường hợp xấu nhất, ta phải đi qua mọi phần tử mới tới được gốc, tức thời gian chạy Θ(N). Vì ta phải gọi `find` cho cả `connect` lẫn `isConnected`, thời gian chạy của cả hai đều bị chặn trên bởi O(N).

### Tóm tắt và mã <a href="#summary-and-code" id="summary-and-code"></a>

N = số phần tử trong cấu trúc DisjointSets của ta

| Triển khai | Hàm khởi tạo | `connect` | `isConnected` |
| ---------- | ------------ | --------- | ------------- |
| QuickUnion | Θ(N)         | O(N)      | O(N)          |
| QuickFind  | Θ(N)         | Θ(N)      | Θ(1)          |
| QuickUnion | Θ(N)         | O(N)      | O(N)          |

Từ bảng thời gian chạy, QuickUnion có vẻ tệ hơn QuickFind! Tuy nhiên hãy nhớ O(N) chỉ là **một cận trên**. Khi các cây tương đối cân bằng, cả `connect` lẫn `isConnected` đều chạy khá nhanh. Ở mục tiếp theo ta sẽ thấy cách _đảm bảo_ chúng luôn chạy tốt.

```java
public class QuickUnionDS implements DisjointSets {
    private int[] parent;

    public QuickUnionDS(int num) {
        parent = new int[num];
        for (int i = 0; i < num; i++) {
            parent[i] = -1;
        }
    }

    private int find(int p) {
        while (parent[p] >= 0) {
            p = parent[p];
        }
        return p;
    }

    @Override
    public void connect(int p, int q) {
        int i = find(p);
        int j= find(q);
        parent[i] = j;
    }

    @Override
    public boolean isConnected(int p, int q) {
        return find(p) == find(q);
    }
}
```
