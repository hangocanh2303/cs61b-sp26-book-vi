# 2. Định nghĩa và sử dụng lớp

LƯU Ý: Chương này vẫn chưa được cập nhật cho Spring 2026, nhưng nội dung của nó không khác quá nhiều so với những thay đổi đã diễn ra kể từ khi chương này được viết.

#### Phương thức tĩnh và không tĩnh <a href="#static-vs-non-static-methods" id="static-vs-non-static-methods"></a>

**Phương thức tĩnh**

Tất cả mã trong Java phải là một phần của một lớp (hoặc thứ gì đó tương tự như một lớp mà chúng ta sẽ tìm hiểu sau). Hầu hết mã được viết bên trong các phương thức. Hãy xem xét một ví dụ:

```java
public class Dog {
    public static void makeNoise() {
        System.out.println("Bark!");
    }
}
```

Nếu chúng ta thử chạy lớp `Dog`, chúng ta sẽ chỉ nhận được thông báo lỗi:

```
$ java Dog
Error: Main method not found in class Dog, please define the main method as:
       public static void main(String[] args)
```

Lớp `Dog` mà chúng ta đã định nghĩa không tự làm gì cả. Chúng ta mới chỉ định nghĩa một điều mà `Dog` **có thể** làm, cụ thể là phát ra tiếng kêu. Để thực sự chạy lớp này, hoặc là ta thêm một phương thức `main` vào lớp `Dog`, như đã thấy ở chương 1.1, hoặc là tạo một lớp [`DogLauncher`](https://www.youtube.com/watch?v=Q-LE-jJQLTM) riêng để gọi các phương thức của lớp `Dog`. Ví dụ, hãy xét chương trình dưới đây:

```java
public class DogLauncher {
    public static void main(String[] args) {
        Dog.makeNoise();
    }
}
```

```
$ java DogLauncher
Bark!
```

Một lớp dùng lớp khác đôi khi được gọi là **client** của lớp đó; ví dụ `DogLauncher` là client của `Dog`. Không có cách nào trong hai cách này luôn tốt hơn cách còn lại: thêm một phương thức `main` vào `Dog` có thể phù hợp hơn trong một số tình huống, còn tách một lớp client như `DogLauncher` có thể phù hợp hơn trong những tình huống khác. Ưu điểm tương đối của từng cách sẽ dần rõ hơn khi ta thực hành thêm trong khóa học.

**Biến thực thể và khởi tạo đối tượng**

Không phải tất cả các con chó đều giống nhau. Một số con chó thích sủa không ngừng, trong khi những con khác lại gầm lên rất vang, mang lại niềm vui cho tất cả những ai nghe thấy tiếng gọi vinh quang của chúng. Thông thường, chúng ta viết các chương trình mô phỏng các đặc điểm của vũ trụ nơi chúng ta sinh sống và cú pháp của Java được tạo ra để dễ dàng cho phép việc bắt chước đó.

Một cách để biểu diễn sự đa dạng của thế giới loài chó là tạo các lớp riêng cho từng loại `Dog`.

```java
public class TinyDog {
    public static void makeNoise() {
        System.out.println("yip yip yip yip");
    }
}

public class MalamuteDog {
    public static void makeNoise() {
        System.out.println("arooooooooooooooo!");
    }
}
```

Như bạn hẳn đã thấy trước đây, các lớp có thể được khởi tạo, và các thể hiện có thể lưu trữ dữ liệu. Điều này dẫn tới một cách tiếp cận tự nhiên hơn: ta tạo ra các thể hiện của lớp `Dog`, rồi để hành vi của các phương thức trong `Dog` phụ thuộc vào thuộc tính của từng `Dog` cụ thể. Để thấy rõ hơn, hãy xét lớp dưới đây:

```java
public class Dog {
    public int weightInPounds;

    public void makeNoise() {
        if (weightInPounds < 10) {
            System.out.println("yipyipyip!");
        } else if (weightInPounds < 30) {
            System.out.println("bark. bark.");
        } else {
            System.out.println("woof!");
        }
    }    
}
```

Để minh họa cách dùng một `Dog` như vậy, hãy xét đoạn mã sau:

```java
public class DogLauncher {
    public static void main(String[] args) {
        Dog d;
        d = new Dog();
        d.weightInPounds = 20;
        d.makeNoise();
    }
}
```

Khi chạy, chương trình này sẽ tạo một `Dog` có cân nặng 20, và `Dog` đó sẽ phát ra tiếng "bark. bark.".

Một số quan sát và thuật ngữ chính:

* Một đối tượng trong Java là một thể hiện (_instance_) của một lớp bất kỳ.
* Lớp `Dog` có các biến riêng, còn được gọi là _biến thực thể_ hoặc _biến không tĩnh_. Chúng phải được khai báo bên trong lớp, không giống như các ngôn ngữ như Python hoặc Matlab, nơi các biến mới có thể được thêm vào khi chạy.
* Phương thức mà chúng ta tạo trong lớp `Dog` không có từ khóa `static`. Ta gọi các phương thức như vậy là **phương thức thực thể** (_instance methods_) hoặc **phương thức không tĩnh** (_non-static methods_).
* Để gọi phương thức `makeNoise`, trước tiên ta phải _khởi tạo_ một `Dog` bằng từ khóa `new`, rồi gọi phương thức trên một `Dog` cụ thể. Nói cách khác, ta gọi `d.makeNoise()` thay vì `Dog.makeNoise()`.
* Khi một đối tượng đã được khởi tạo, nó có thể được _gán_ cho một biến đã được _khai báo_ với kiểu phù hợp, ví dụ: `d = new Dog();`
* Các biến và phương thức của một lớp còn được gọi là _thành viên_ của một lớp.
* Các thành viên của một lớp được truy cập bằng _dot notation_.

**Các hàm tạo trong Java**

Như có lẽ bạn đã thấy trước đây, trong các ngôn ngữ hướng đối tượng ta thường tạo đối tượng bằng _constructor_:

```java
public class DogLauncher {
    public static void main(String[] args) {
        Dog d = new Dog(20);
        d.makeNoise();
    }
}
```

Ở đây, quá trình khởi tạo được tham số hóa, giúp chúng ta tiết kiệm thời gian và tránh sự lộn xộn khi nhập thủ công nhiều phép gán biến mẫu có thể có. Để kích hoạt cú pháp như vậy, chúng ta chỉ cần thêm một "hàm tạo" vào lớp Dog, như hiển thị bên dưới:

```java
public class Dog {
    public int weightInPounds;

    public Dog(int w) {
        weightInPounds = w;
    }

    public void makeNoise() {
        if (weightInPounds < 10) {
            System.out.println("yipyipyip!");
        } else if (weightInPounds < 30) {
            System.out.println("bark. bark.");
        } else {
            System.out.println("woof!");
        }    
    }
}
```

Hàm tạo có chữ ký `public Dog(int w)` sẽ được gọi bất cứ khi nào chúng ta cố gắng tạo một `Dog` bằng cách sử dụng từ khóa `new` và một tham số số nguyên duy nhất. Đối với những bạn đến từ Python, hàm tạo rất giống với phương thức `__init__`.

**Tóm tắt thuật ngữ**

**Khởi tạo mảng, mảng đối tượng**

Như chúng ta đã thấy trong HW0, các mảng cũng được khởi tạo trong Java bằng từ khóa new. Ví dụ:

```java
public class ArrayDemo {
    public static void main(String[] args) {
        /* Create an array of five integers. */
        int[] someArray = new int[5];
        someArray[0] = 3;
        someArray[1] = 4;
    }
}
```

Tương tự, chúng ta có thể tạo các mảng đối tượng được khởi tạo trong Java, ví dụ:

```java
public class DogArrayDemo {
    public static void main(String[] args) {
        /* Create an array of two dogs. */
        Dog[] dogs = new Dog[2];
        dogs[0] = new Dog(8);
        dogs[1] = new Dog(20);

        /* Yipping will result, since dogs[0] has weight 8. */
        dogs[0].makeNoise();
    }
}
```

Hãy quan sát rằng new được sử dụng theo hai cách khác nhau: Một lần để tạo một mảng có thể chứa hai đối tượng `Dog` và hai lần để tạo mỗi `Dog` thực tế.

#### Phương thức lớp so với Phương thức thực thể <a href="#class-methods-vs-instance-methods" id="class-methods-vs-instance-methods"></a>

Java cho phép chúng ta định nghĩa hai loại phương thức:

* Phương thức lớp, hay còn gọi là phương thức tĩnh.
* Phương thức thực thể, hay còn gọi là phương thức không tĩnh.

Phương thức thực thể là những hành động chỉ có thể được thực hiện bởi một thể hiện cụ thể của một lớp. Phương thức tĩnh là những hành động được thực hiện bởi chính lớp đó. Cả hai đều hữu ích trong những hoàn cảnh khác nhau. Ví dụ về phương thức tĩnh là `sqrt` của lớp `Math`. Vì nó là phương thức tĩnh, ta có thể gọi nó như sau:

```java
x = Math.sqrt(100);
```

Nếu `sqrt` là một phương thức thực thể, ta sẽ phải dùng cú pháp vụng về dưới đây. May mắn thay, `sqrt` là phương thức tĩnh nên trong chương trình thật ta không phải làm vậy.

```java
Math m = new Math();
x = m.sqrt(100);
```

Đôi khi, việc một lớp có cả phương thức tĩnh lẫn phương thức thực thể là hoàn toàn hợp lý. Ví dụ, giả sử ta muốn có khả năng so sánh hai con chó. Một cách để làm điều này là thêm một phương thức tĩnh dùng để so sánh các `Dog`.

```java
public static Dog maxDog(Dog d1, Dog d2) {
    if (d1.weightInPounds > d2.weightInPounds) {
        return d1;
    }
    return d2;
}
```

Phương thức này có thể được gọi như sau:

```java
Dog d = new Dog(15);
Dog d2 = new Dog(100);
Dog.maxDog(d, d2);
```

Hãy quan sát rằng chúng ta đã gọi bằng tên lớp, vì phương thức này là một phương thức tĩnh.

Ta cũng có thể cài đặt `maxDog` như một phương thức không tĩnh, ví dụ:

```java
public Dog maxDog(Dog d2) {
    if (this.weightInPounds > d2.weightInPounds) {
        return this;
    }
    return d2;
}
```

Ở trên, chúng ta sử dụng từ khóa `this` để chỉ đối tượng hiện tại. Phương thức này có thể được gọi, ví dụ, với:

```java
Dog d = new Dog(15);
Dog d2 = new Dog(100);
d.maxDog(d2);
```

Ở đây, chúng ta gọi phương thức này bằng cách sử dụng một biến thể hiện cụ thể.

public static Dog maxDog(Dog d1, Dog d2) {

**Biến tĩnh**

Đôi khi việc một lớp có biến tĩnh cũng rất hữu ích. Đây là các thuộc tính thuộc về chính lớp đó, chứ không phải thuộc về từng thể hiện. Ví dụ, ta có thể ghi lại rằng tên khoa học (binomen) của chó là `"Canis familiaris"`:

```java
public class Dog {
    public int weightInPounds;
    public static String binomen = "Canis familiaris";
    ...
}
```

Các biến tĩnh nên được truy cập bằng tên của lớp thay vì một thể hiện cụ thể, ví dụ: bạn nên sử dụng `Dog.binomen`, không phải `d.binomen`.

Mặc dù về mặt kỹ thuật Java cho phép bạn truy cập biến tĩnh thông qua tên của một thể hiện, đó là cách viết xấu, dễ gây nhầm, và theo tôi là một quyết định không hay của những người thiết kế Java.

#### public static void main(String\[] args) <a href="#public-static-void-mainstring-args" id="public-static-void-mainstring-args"></a>

Với những gì chúng ta đã học được cho đến nay, đã đến lúc làm sáng tỏ tuyên bố mà chúng ta đã sử dụng cho phương thức main. Chia nó thành từng mảnh, chúng ta có:

* `public`: Cho đến thời điểm này, mọi phương thức của ta đều bắt đầu bằng từ khóa này.
* `static`: Đây là phương thức tĩnh, không gắn với bất kỳ thể hiện cụ thể nào.
* `void`: Nó không có kiểu trả về.
* `main`: Đây là tên của phương thức.
* `String[] args`: Đây là một tham số được truyền cho phương thức chính.

**Đối số dòng lệnh**

Vì `main` được gọi bởi chính trình thông dịch Java chứ không phải bởi một lớp Java khác, nên nhiệm vụ của trình thông dịch là cung cấp các đối số này. Thông thường, chúng chính là các đối số dòng lệnh. Ví dụ, hãy xét chương trình `ArgsDemo` dưới đây:

```java
public class ArgsDemo {
    public static void main(String[] args) {
        System.out.println(args[0]);
    }
}
```

Chương trình này in ra đối số dòng lệnh thứ 0, ví dụ:

```
$ java ArgsDemo these are command line arguments
these
```

Trong ví dụ trên, `args` sẽ là một mảng các chuỗi, trong đó các phần tử là `{"these", "are", "command", "line", "arguments"}`.
